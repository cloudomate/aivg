Feature 025 adds **Opus on the UPSTREAM (mic→gateway→STT) gRPC path** — the symmetric counterpart to 024's downstream Opus — so a native satellite compresses its mic uplink (~10× less bandwidth) instead of streaming raw 16 kHz PCM; the gateway decodes Opus before STT. **Additive wire change**: add `OpusChunk opus = 4` to `ClientFrame` (self-describing arm) + `SessionHeader.upstream_codec_pref` in `proto/aivg/satellite/v1/audio.proto`; regenerate Python **and** C++ bindings; contract **0.3.0→0.4.0** (additive). **Clarified decisions (2026-06-04)**: device C++ `GrpcTransport::send_mic` Opus-encodes at 48 kHz via the existing `OpusBridge` (no on-device decimation; `mic_down` dropped); **capture rate is negotiation-dependent (Option C)** — `mic_frame_samples()` = 960 (Opus) / 320 (PCM), no on-device resampler; gateway `push_inbound_opus` decodes Opus→48 kHz→Session. **STT-rate refinement**: code shows STT already runs at **48 kHz** (`session.py` `transcribe(sample_rate=48000)`), so the Opus path decodes to 48 kHz and joins the existing pipeline — NO separate 16 kHz step (departs from the literal clarification; flagged). **Handshake**: the device must know acceptance before picking a capture rate, so the gateway advertises upstream-Opus acceptance in the **register/capability reply** (the C++ control plane already reads `chosen_transport` there pre-voice). Reuses PyAV libopus (gateway) + `OpusBridge` (device) — no new deps.
