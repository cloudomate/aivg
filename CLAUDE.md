Feature 023 fixes the **gateway gRPC voice transport's downstream audio**: `GrpcMediaAdapter.send_audio` (in `src/aivg_core/transports/grpc/media_adapter.py`) was queuing the **raw, provider-encoded TTS clip** straight into its 48 kHz PCM queue (`_out`) and then running the existing 48 kHz→16 kHz downsample over bytes that were never 48 kHz PCM — so gRPC satellites played noise. The WebRTC path (`webrtc/signaling.py:send_audio`) already decodes correctly via **PyAV (in-process ffmpeg)**: `av.open` + `av.AudioResampler(format="s16", layout="mono", rate=48000)`. The fix gives the gRPC adapter the same decode-and-resample-to-48 kHz step (reusing `PcmFramer` for 20 ms framing), lifted into one neutral helper `src/aivg_core/audio/tts_decode.py` so both transports share it and can't diverge again. **Internal-only**: no proto/wire change, no client change; the existing client-side 16↔48 resampling (feature 022 C++ SDK) depends on this gateway half. Constitution Check: PASS (gateway audio *plumbing*, not STT/TTS — Principle I; removes a per-transport divergence — Principle II; Principle V requires an end-to-end live proof on a non-48 kHz provider clip).
