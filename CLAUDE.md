Feature 022 adds a **gRPC transport to the C++ SDK `libaivg-sat`** (sdks/cpp/, feature 020) — the native-device counterpart that delivers feature 021's reliable audio plane end-to-end on real hardware. Consumes the **same** canonical `proto/aivg/satellite/v1/` contract (no wire change). **Phase 1** = audio plane: one `Audio.Stream` (raw 16 kHz PCM up — no on-device Opus encode; codec-tagged audio + transcripts + events down). Key refactor: there's **no transport seam today** (`LibpeerTransport` is concrete, held directly by `VoiceSession`), so the feature introduces an abstract `Transport` interface (audio/lifecycle/event altitude, NOT SDP) and slots both WebRTC + gRPC behind it. **CENTRAL DECISION (Constitution V)**: RPi Zero 2 W/POSIX tier ships full `grpc++` (the MVP); **ESP32-S3 stays on WebRTC** — `grpc++` doesn't fit/port to ESP-IDF, so an on-device gRPC path (nanopb + minimal HTTP/2) is deferred behind a *measured* hardware spike (US2). gRPC is `AIVG_SAT_ENABLE_GRPC`, POSIX-only (ESP build never sees grpc++). Enabled by the **v2.1.0** transport-neutral Principle III amendment. Public API additive; existing WebRTC integrations unchanged.
