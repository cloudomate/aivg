Feature 024 removes the lossy **48 kHz→16 kHz→48 kHz** downstream double-resample for 48 kHz-native gRPC devices (rpi-pipewire; XVF3800 is I2S-48 kHz). **PIVOT (per maintainer decision): solved via Opus, NOT a new PCM-48k codec.** Opus is internally always 48 kHz, so the fix is to encode downstream Opus at **native 48 kHz** instead of the old 16 kHz, skipping the downsample — a **gateway-only change, NO wire/proto/contract change** (CODEC_OPUS already exists; contract stays 0.3.0). A device that decodes Opus at 48 kHz (the C++ `OpusBridge` already does) instantly gets full band; a 16 kHz-decoder device still decodes the same packets. Encoder is **PyAV's bundled libopus** (PyAV is already a hard dep → Opus now always producible, no `opuslib`/system-libopus install). Code: `codec.py` `_opus_available()` now checks PyAV libopus; new stateful `codec.OpusEncoder48k`; `GrpcMediaAdapter.run_outbound_pump` encodes Opus natively (no downsample) + flushes the encoder tail; raw-PCM path unchanged (still 16 kHz). A client must still **advertise** `[OPUS,…]` to get it (best-first pref). Constitution: PASS (audio plumbing not STT/TTS — I; per-session preference not device_type branching — II; 48 kHz is XVF3800-native per Principle V, wants a live Opus-48k proof on `iva`). NOTE: spec/plan/research/tasks under `specs/024-…` still describe the original PCM-48k approach; superseded by this Opus pivot.
